# 神州租车云端车源监控

监控大庆东站服务点同网点取还：2026年10月17日08:00取车，10月18日08:00还车（北京时间）；目标特斯拉或日产N7。

## 查询方式

v4使用 Python Playwright 的 APIRequestContext，按官网网页本身使用的公开查询协议建立HTTPS会话，不依赖H5城市选择器。程序不登录、不创建订单。

每轮重新进行四次真实官网查询：

1. 从官网城市列表中确认唯一的“大庆”及城市编号。
2. 按完整租期确认“大庆东站服务点”的编号、地址和取车营业状态。
3. 按同一网点编号和完整租期再次确认还车营业状态。
4. 按已核验的城市、网点、完整租期查询实际车型列表，严格匹配响应网点。

使用的官网接口为 `cityList/v1`、`deptList/v1`、`chooseCar/v3`；参数和库存含义来自官网公开前端脚本。车型列表可能包含附近网点，程序只采用编号和全名均匹配东站服务点的列表。仅匹配车型名称字段，候补库存（2/3）不发送有车通知；不认识的库存状态、重复车型、缺失价格或查询失败全部记为 `unknown`。

## 自动运行

GitHub Actions每小时第7、37分钟计划检查，也可以手动运行。实际启动可能因GitHub调度延后。到2026年10月17日08:00（北京时间）后停止官网查询与通知。

- `monitor`：正常监控；新出现或确认消失后重新出现的目标车型才推送。
- `diagnose`：进行真实查询并保存报告，不推送，不改变已发送通知的去重集合。
- `test_push`：只测试Bark通道，不查车源。

## 查看状态

Actions每轮摘要显示真实结果和核验车型数量。

- `state.json`：本轮状态、最近检查和成功核验时间、连续失败次数、查询条件、网点编号、车型清单和通知状态。
- `history.json`：最近240轮状态摘要。
- `monitor-result-运行编号-尝试编号` artifact：每轮安全检查报告。

| 状态 | 含义 |
|---|---|
| `notfound` | 官网查询和东站完整车型列表已核验，目前无目标可选车型 |
| `possible` | 官网在指定条件下列出目标可选车型，实际库存及价格以预订时为准 |
| `unknown` | 本轮无法完成严格核验，不表示无车，保留之前通知去重集合 |
| `stopped` | 已到取车时刻，停止查询与通知 |

查询未确认或推送失败会让Actions显示失败；状态保存和报告上传仍会执行。Bark发送失败时不确认该车型已通知，后续准确匹配后重试。

## 凭证

`BARK_KEY`只保存在GitHub Actions Secrets。代码、状态、报告和日志均不保存该值。查询会话不需要登录凭证，也不读取原有登录Secret。程序不持久化Cookie、授权头、账户信息或原始响应。
