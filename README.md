## 查询与安全条件

当前Actions运行 `monitor_all.py`；原始东站程序 `monitor.py` 保留，未改动。

程序使用Python Playwright的APIRequestContext请求官网公开接口 `cityList/v1`、`deptList/v1`、`chooseCar/v3`。每轮确认大庆城市编号、网点清单、完整租期和响应网点对应的车型列表。候补库存不推送，未知库存或缺少完整列表会明确记录为失败，不当作无车。程序不登录、不创建租车订单。

只有本轮真实核验的符合条件车型才进入新增通知。通知包含网点、车型、价格、取还车时间；Bark的HTTP状态及JSON成功码均须确认成功。去重键包含完整租期，更换租期不会被此前已通知车型阻止。

## 状态和验证

- `state_all.json`：最新车源、成功检查网点、失败网点、核验时间和通知状态。
- `history_all.json`：最近240轮状态摘要。
- Actions的 `monitor-result-运行编号-尝试编号` artifact：本轮检查报告，保留14天。

`health=ok` 表示本轮查询完整；`partial` 表示部分网点失败；`unknown` 表示无法完成核验；`push_failed` 表示通知发送未确认。Actions显示成功不能替代对这些字段的检查。`verified_utc` 使用UTC时间，北京时间加8小时。失败网点后续继续重试。

GitHub Actions配置每小时第0、10、20、30、40、50分钟计划运行，并以自续链补充调度。工作流串行执行，重复等待任务可能被GitHub合并取消。保存状态和报告在查询失败后仍会执行。

`python -m unittest -v test_monitor` 检查安全与通知逻辑。构造数据只用于回归检查，不能当作真实车源验证；最新真实结果以状态文件及Actions报告为准。
